# Working folders

One folder per piece of work: a problem being investigated, a change being made, an idea
being explored. The list is [index.md](index.md), generated by `uv run records/reindex.py`
from each folder's README; never hand-edit it.

## Name

`<YYMMDD>_<type>_<slug>/` — e.g. `260101_problem_door_sticks/`

- `YYMMDD`: the day it started. A second folder that day gets `YYMMDD-2_`, then `-3_`.
- `type`: `problem`, `change` or `idea`, as it stood at the start.
- `slug`: 2–3 lowercase words joined by `_`. A problem names what fails, not the suspected
  cause; a change names the capability, not the implementation; an idea names the goal.

**The name is permanent.** Other files link to it. Never rename or move a folder to show what
happened to the work; that lives in its README. The one exception: once a year, folders from
earlier years may move to `archive/<YYYY>/`.

## The folder's README

```
---
type: problem          # problem | change | idea — may change; History says when
status: active         # active | blocked | parked | done | abandoned | superseded
weight: standard       # light | standard | full
started: YYYY-MM-DD
closed:
branch:                # git only; empty otherwise
base_commit:           # git only: `git rev-parse --short HEAD` at the start, `none` if no commits yet
merged_commit:         # git only
superseded_by:         # folder name
decisions: []          # numbers of the records this folder produced, e.g. [0002]; each record's `source` names this folder
---

# Title

Three sentences: what this is about.

## History
- YYYY-MM-DD — anything that changed the shape of the work: type changed, blocked on what,
  hypothesis dropped, parked (and "back when …"), handed to another model.
```

Other files in the folder are named by what they contain — `analysis.md`, `options.md`,
`test_results.md`, `plan.md` — not by phase number.
